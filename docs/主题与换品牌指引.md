# 主题与换品牌指引

## 1. 主题链路

```
frontend/theme/brand.json     ← 唯一色值来源
        │
frontend/tailwind.config.js   ← 生成 daisyUI 主题（品牌名 / 品牌名-dark）
        │
tailwindcss + daisyui 构建
        │
src/TailAdmin.Templates.Rcl/wwwroot/css/tailadmin.css  ← 产物入库
        │
<html data-theme="als"> / <html data-theme="als-dark" class="theme-dark">
```

- 明暗主题名分别为 `{BrandName}` 与 `{BrandName}-dark`；
- `data-theme` 控制 daisyUI 组件色板，`theme-dark` 类控制 Tailwind `dark:` 变体；
- 首屏防闪烁脚本在布局 `<head>` 内联执行，读取 `localStorage["ta-theme"]`，其次 `AdminUi:DefaultTheme`，最后跟随系统。

## 2. 换品牌色

1. 修改 `frontend/theme/brand.json` 中 `light` / `dark` 两组色值（以及圆角、按钮动效变量）。
2. 如需换主题名，同步修改 `AdminUi:BrandName`（appsettings）与布局/JS 使用的品牌名（配置文件均已参数化）。
3. 重新构建产物：

```powershell
./build/build-frontend.ps1
```

4. 提交 `brand.json` 与生成的 `tailadmin.css`，确保未装前端工具链的机器也能编译运行。
5. 检查页面无硬编码色值：业务样式只允许使用 `primary / success / warning / error / base-*` 等主题类。

## 3. 新增一套品牌主题

在 `brand.json` 中新增一组 `{name, light, dark}`（或新增文件），在 `tailwind.config.js` 的 `daisyui.themes` 中注册：

```js
themes: [
  { [brand.name]: brand.light },
  { [`${brand.name}-dark`]: brand.dark },
  { "other": { ... } },
  { "other-dark": { ... } }
]
```

同时扩展布局的主题名映射（`AdminUi:BrandName` 决定后缀拼接方式）。未使用的主题也应保留在两套主题体系中，避免临时新增。

## 4. 视觉约束

- 卡片：`ta-card` / `ta-card-pad`；页面骨架：`ta-shell`、`ta-sidebar`、`ta-topbar`、`ta-content`；
- 间距与圆角只使用 Tailwind / daisyUI 语义类，不写随机像素；
- 图标统一使用 RCL 的 `_Icon` partial（Heroicons 线性图标），业务页不直接引图标库；
- 新增页面必须复用现有布局与组件，保持导航、表头、按钮尺寸、空态一致。

## 5. 版本与依赖锁定

| 依赖 | 版本 | 备注 |
| --- | --- | --- |
| tailwindcss | 3.4.19 | 锁定 3.4.x |
| daisyui | 4.12.24 | 必须与 Tailwind 3.4 成对升级 |
| alpinejs | 3.14.9 | 3.x |
| @tanstack/table-core | 8.21.3 | 服务端分页模式 |
| flatpickr | 4.6.13 | 按需引入 |
| esbuild | 0.28.2 | 仅构建期 |

升级任何一项都必须单独提交，并附上 `tailadmin.css` / `tailadmin.js` 的产物 diff。Tailwind 与 daisyUI 大版本不得混用。

## 6. 已知边界

- 为兼容 layui 等旧样式，Tailwind 关闭了 `preflight`，所有基础重置限定在 `.ta-app` 作用域内；
- RCL 只提供主题变量与组件类，不接管宿主全局样式；
- 迁移期不得同时在页面引入两套 CSS 框架的基础 reset。
